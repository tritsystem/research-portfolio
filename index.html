Low-level systems

spikeling-os Rust · active

A from-scratch x86_64 kernel with its own filesystem, ELF loader, processes and a subset-C compiler that runs inside it, built one verified milestone at a time. Each milestone has two QEMU boots and self-tests whose expected values are worked out by hand.

Differential fuzzing of the in-kernel compiler found and fixed real silent miscompiles: integer literals of 232 or more truncated to 32 bits, case labels outside the 32-bit range compared by their low 32 bits, and a continue inside a switch inside a loop dropped since Milestone 91. The last one was found only after the fuzz started reporting how often it generated each combination of constructs. Its first run had produced that combination 0 times in 800 programs.

Native seam audit procedure

A procedure for auditing the native boundary of ML libraries, where Python hands buffers to C, C++ and CUDA. Before any tool is trusted, it's validated on a planted bug and a clean control: 9 sanitizer and fuzzer configurations, including four compute-sanitizer tools on an RTX 5060.

It records blind spots instead of hiding them: synccheck didn't flag a divergent __syncthreads on sm_120, and the first tool inventory wrongly said valgrind was installed, which only the planted bug exposed. Procedure

pytest-numba-cache Python · finished

A pytest plugin that gives each parallel worker its own numba cache, fixing a cache-write race. Measured: crashes in 8 of 10 rounds without it and 0 of 10 with it, and 76 of 160 librosa processes crashed on a shared cache versus 0 with separate ones. Measured on Windows only.

baton Python · active

Three LoRA adapters sharing one frozen model, each with its own pre-filled KV cache. Hardening found a cache-position bug where re-warming left every later write outside the attention mask, ending in a CUDA device-side assert. The fix raises before any GPU write, and a mutation check proves the test catches it.

ML research

The ML research is where I learned to measure: pre-registered studies of spiking neural networks, ternary weights and physical reservoirs. Most of the results are bounded or negative, and they're reported that way.

Spikeling Python/C · active

A language and runtime for spiking neural networks: one .spk file runs on Python, C, Verilog and GDScript backends.

Measured both ways. Event-driven execution was 16–29× faster at 5% activity but 0.92× at 100%. The resonator neuron beat a naive threshold but not Goertzel or FFT, and SNN scheduling was falsified as a differentiator (identical to greedy graph colouring).

Heterogeneous neuron ensembles study line

Do mixed neuron types detect more kinds of anomaly than one type? In Python, a mixed ensemble scored 60/60 versus 30/60 for all-LIF (heterogeneous-neuron-ontology).

The kernel port went through a full retraction: the original 16/16 result was a false positive, because its thresholds were calibrated on too few quiet windows. After that was fixed it was an honest negative (12 vs 12). A properly configured, frequency-corrected resonator then gave a measured 29/32 versus 12/32 for all-LIF, with 1/32 false positives on held-out quiet data (spikeling-os Milestones 165–175).

Ternary weights and OBSERVE Python · active

Ternary research that produced OBSERVE, a local semantic code search tool. Ternary weights gave 20× compression but cost 7.35 points of accuracy, against INT8's 0.19-point gain. So the search API serves float32, because ternary changed the top result 40% of the time.

OBSERVE used 66% fewer tokens on its own benchmark, but grep beats it (5/5 vs 3/5) when you know the identifier. The hosted API (observe-api) is code-complete but not currently deployed.

methodlm Python · active

A causal-reasoning harness that makes a model back causal claims with real tests and a checkable ledger. Its backdoor-adjustment test cut false causal claims from 100% to about 1% while keeping the true cause. Its value depends on the model's capability, and it says so.

Physical reservoirs simulation studies

topological-phononics (Zenodo preprint): topological structure protects a reservoir against a dead element exactly when chiral symmetry holds, and the idealized ~5× does not transfer to a realistic device.

quasicrystal-mems-reservoir: a symmetry selection rule confirmed on finite-element modes to 1 part in 109, with a bounded advantage. The "richer structure computes better" intuition was disproven.

silicon-mega-accelerator and spikegate finished

Accelerator techniques applied to Spikeling: a bit-exact 25.6× speedup from sparse indexing, while a lookup-table exp() was 1.56× slower than math.exp. spikegate's spike-gated routing lost to an if/elif cascade by ~21× on decision speed, and its README says so first.

Tools I built for the hunt

reagent

A two-stage bug assay: 40 detectors (32 Python, 8 C) nominate code from AST patterns, then confirm() imports and probes the code. Each detector has a synthetic ground-truth benchmark. Most sweeps of new repos end with zero real findings after triage, and that's reported.

crawlspike

A static crawler for "one path honors a flag, its sibling drops it". It found a known bug from Spikeling that ruff, semgrep and pylint all miss. On real OSS its first runs found 5 bugs in itself and 0 in the targets.

sec-portfolio pipeline

The track-record site is regenerated from the real merged diffs, with no model in the loop, so it can't hallucinate a fix.

mcp-gateway private

A tamper-evident, hash-chained audit log and rate limiter for local agent tool servers, imported by OBSERVE's and Spikeling's MCP servers.

How I learn

The method

Everything above runs on one written discipline, the Method, which opens: "A result is worth exactly as much as the test that could have broken it and didn't." In practice:

  • Measure, don't infer. Reading code is a hypothesis about what it does. Run it.
  • Validate the instrument first. Every new harness gets a planted case it must fail before its zero is trusted.
  • Pre-register the verdict, success and failure both, before looking at the result.
  • Report the worst slice, not the average, and ask what the laziest trick would score.
  • Find the exact edge of every rule: state results as "A beats B exactly when C holds".
  • A documented no is a result, and overclaims are retracted by name, in writing.

The evidence ladder

Every finding states the tier it reached, and I never round up. A finding needs at least T3, and I file at T4.

T0
A static detector or grep hit. A lead.
T1
Code read by hand and reasoned through, nothing run. A lead.
T2
The real function run, but outside its real caller. Still a lead, never called confirmed.
T3
Reproduced through the real target's real input path. The minimum to call it a finding.
T4
T3, plus a fix that flips the same reproduction from red to green, with the project's own tests still passing.
T5
T4, plus a stated search of sibling code for the same root cause, every candidate resolved, and a guard for the whole bug class.

Example lesson titles: a finding counts only when execution-verified, reproducible and fixable; use an fp64 control before calling a numerical violation a bug; print the imported module path before trusting a harness; a mean-plus-k-sigma threshold from few windows can be vacuous.

Catching my own mistakes

  • A long-reported pass was retracted. A held-out control showed a 16/16 result was a false positive: one detector fired identically on every input. The fix's own first gate also failed, and it stays on record.
  • A clean fuzz meant nothing for constructs it never generated. Measuring coverage per construct combination exposed a gap, and closing it found a miscompile that had been present for 75 milestones.
  • The hypothesis held for a different reason than predicted. The predicted mechanism missed, an off-kernel replay of the exact update rule diagnosed why, and the correction was tested as a new pre-registered experiment instead of patched in after the fact.
  • A tool inventory was wrong, and only a planted bug showed it.
